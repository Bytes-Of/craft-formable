# Editions: Pro feature gate audit

Formable ships in two editions - **Lite** and **Pro**. Every Pro feature must
degrade _gracefully_ in Lite: an upgrade prompt or a quiet no-op, never a raw
error or a dead editable control.

The gate is a single choke-point - [`Plugin::isPro()`](../src/Plugin.php) on the
server, `store.isPro` in the form builder, and `craft.formable.isPro` in
front-end templates. This table is the audit baseline; re-run it against both
editions after any gating change.

| Pro feature                             | Gate site (server)                                                                                                                                                          | Lite runtime behaviour                                                         | Upgrade surface (Lite UI)                                                                                                         |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| **Conditional logic**                   | [`Conditions::isEnabled()`](../src/services/Conditions.php) - gates `resolve` / `getVisibleFields` / `getVisiblePageIndexes`                                                | Every page and field resolves visible; authored rules ignored, nothing blanked | `ConditionsEditor.vue` → `<UpgradePrompt feature="Conditional logic">` (page, field, notification & integration conditions)       |
| **Save & resume**                       | [`SubmissionsController::actionResume()`](../src/controllers/SubmissionsController.php) (404s) + `handleSave()` (rejects)                                                   | No resume link is issued; a stray link 404s; the save path refuses             | `FormSettingsPanel.vue` locked control + `<UpgradePrompt>`; default `_nav.twig` hides the save button                             |
| **Captchas**                            | [`Captchas::getCaptchaForForm()`](../src/services/Captchas.php) (returns null)                                                                                              | No challenge is rendered or verified                                           | `FormSettingsPanel.vue` locked captcha picker; `_settings.twig` captcha-keys section → `upgrade.prompt`                           |
| **Integration forwarding**              | [`Integrations::sendForSubmission()`](../src/services/Integrations.php) (early return)                                                                                      | Config saves, but no submission is ever forwarded                              | `IntegrationsPanel.vue` panel prompt; CP `integrations/_index` & `_edit` → `upgrade.prompt` (configure now, activates on upgrade) |
| **Conditional notifications**           | [`Notifications::sendForSubmission()`](../src/services/Notifications.php)                                                                                                   | Every enabled notification simply sends (no condition filtering)               | Notification conditions editor → `<UpgradePrompt>` (shared with Conditional logic)                                                |
| **Data retention purge**                | [`Submissions::purgeForRetention()`](../src/services/Submissions.php) (no-op)                                                                                               | Submissions are kept; nothing is auto-deleted                                  | `FormSettingsPanel.vue` locked retention controls + `<UpgradePrompt>`                                                             |
| **Weekly digest**                       | [`Digest::run()`](../src/services/Digest.php) + [`DigestController`](../src/console/controllers/DigestController.php)                                                       | Cron run is a no-op                                                            | `_settings.twig` digest section → `upgrade.prompt`                                                                                |
| **Member self-service submissions**     | [`SubmissionsController`](../src/controllers/SubmissionsController.php) own-submission actions (edition, then `FormSettings::$enableSelfService`, off by default even on Pro) + [`FormableVariable::submissions()`](../src/variables/FormableVariable.php) | Front-end own-submission query matches nothing; edit/delete actions refuse            | Templating: `craft.formable.submissions` loops empty; no control shown                                                            |
| **Submission edit history**             | [`ManageSubmissionsController`](../src/controllers/ManageSubmissionsController.php)                                                                                         | History is not loaded                                                          | CP `submissions/_edit` history panel gated with the upgrade badge                                                                 |
| **Scheduled forms & submission limits** | [`Form::isAcceptingSubmissions()`](../src/elements/Form.php)                                                                                                                | Schedule window / max-submissions never consulted                              | `FormSettingsPanel.vue` (Pro-only schedule settings)                                                                              |
| **Per-site translations**               | [`Translations::isEnabled()`](../src/services/Translations.php) - gates `localizePages()`/`localizeSettings()`/`settingString()`, applied before a layout is ever hydrated  | Every rendered string is the base value; stored overrides are kept but unread  | `TranslationsPanel.vue` → `<UpgradePrompt>` in place of the editing panel                                                         |
| **Per-form brand palette**              | [`Rendering::resolvePalette()`](../src/services/Rendering.php) - returns the global `Settings::$palette` alone, never merging a form's own                                            | The global palette renders on every form; a form's stored override is ignored, not just hidden | `FormSettingsPanel.vue` locked Appearance controls + `<UpgradePrompt>` (the six `palette*` fields carry `proOnly`)          |
| **GraphQL API**                         | [`Plugin`](../src/Plugin.php) GraphQL registration                                                                                                                          | Types/queries not registered                                                   | N/A (headless surface)                                                                                                            |

## Verifying in the dev site

Switch edition with `php craft plugin/edition formable lite` (or `pro`) and walk
the checklist: confirm each Lite behaviour and upgrade surface above, and that a
normal form still renders and submits with no error.
